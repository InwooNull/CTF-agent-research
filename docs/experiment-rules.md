# 실험 규칙

세 에이전트를 공정하게 비교하기 위해 팀이 합의한 조건. 실험 중 바뀌면 날짜와 이유를 아래 변경 기록에 남긴다.

## 고정 조건

| 항목 | 값 | 비고 |
| --- | --- | --- |
| LLM | `claude-haiku-4-5-20251001` (확정) | 예산과 세 에이전트 동작 검증 기준으로 선정. 여유가 있으면 일부 문제를 `claude-sonnet-4-6`으로 추가 실험 |
| 에이전트 설정 | 각 에이전트의 카테고리별 기본 설정 | EnIGMA `config/ctf/ctf_<카테고리>.yaml`, D-CIPHER `configs/dcipher/<카테고리>_planner_executor.yaml`(자동 선택) |
| 응답 길이 상한 (max_tokens) | 4096 (확정) | 본 실험 전 baseline(코드에 1024 고정)과 EnIGMA(8192)를 4096으로 수정 |
| 최대 라운드 | 미정 (baseline 기본값 3은 너무 작음) | 스모크 테스트 baseline은 30 |
| 문제당 비용 상한 | $1.00 (잠정) | EnIGMA `--per_instance_cost_limit`, D-CIPHER `--max-cost`, baseline `base_config.yaml`의 `max_cost` |
| 문제당 반복 실행 | 3회 (잠정) | 결과 편차 대비 |
| 문제셋 | `problems.md` 참고 | 27문제 확정 (스모크 테스트용 1문제 별도) |
| 실행 환경 | 송인우 PC (x86, WSL2 + Docker) | 세 에이전트 모두 같은 PC에서 실행. arm64 맥은 에뮬레이션으로 속도와 디버거 동작이 달라 제외 |

## 주의 사항

- 비용 검사는 모델 호출이 끝난 뒤에 이루어지므로, 실제 비용이 상한을 조금 넘을 수 있다. 결과에는 실제 비용을 기록한다.
- 설정 하나로 결과와 비용이 크게 달라진다 (`runs/smoke/enigma.md` 참고). 실행 명령과 설정 파일을 매번 기록한다.
- **성공 판정은 "에이전트가 제출한 플래그가 정답과 일치"로 통일한다.** D-CIPHER는 출력 어디에든 플래그가 보이면 자동으로 성공 처리하므로(`runs/smoke/dcipher.md`), 본 실험 전에 이 기능을 끈다.
- 스모크 테스트는 평가 문제셋과 겹치지 않는 development split 문제(`2016q-for-kill`)로 한다. 문제 설명에 플래그가 있는 `leaked_flag`는 D-CIPHER에서 무효이므로 쓰지 않는다.

## 기록 항목

각 실행마다 아래를 `runs/results.csv`에 한 줄씩 기록한다.

- 에이전트, 문제, 회차, 사용 모델
- 결과: 성공 / 실패
- 풀이 시간 (시작~종료)
- 입력·출력 토큰 수, 비용
- 턴 수, 도구 호출 수
- 실패 시 실패 유형 (아래 분류)

## 실패 유형 분류

| 코드 | 유형 | 판단 기준 |
| --- | --- | --- |
| F1 | 가짜 플래그 | 근거 없이 플래그 형식만 맞춰 제출 |
| F2 | 중도 포기 | 에이전트가 스스로 종료·포기 |
| F3 | 반복·정체 | 같은 명령이나 접근을 반복하다 한도 도달 |
| F4 | 한도 초과 | 진전은 있었으나 비용·턴 한도에 걸림 |
| F5 | 환경 오류 | Docker, 네트워크, 도구 오류 등 에이전트 외부 원인 |

## 분석 범위

- 모델 내부 추론은 볼 수 없으므로, 토큰 소모의 원인 분석은 에이전트 구조(호출 횟수, 컨텍스트 전달 방식)까지만 한다.
- 구모델 결과는 직접 재실험하지 않고 논문 공개 수치를 기준선으로 쓴다.
